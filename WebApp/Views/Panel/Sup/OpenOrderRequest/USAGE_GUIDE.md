# راهنمای استفاده - مدیریت درخواست‌های باز

## 🎯 نحوه استفاده

### 1. افزودن کامنت ساده

**مراحل:**
1. وارد صفحه Edit درخواست شوید
2. روی دکمه "افزودن کامنت" کلیک کنید
3. تاریخ و توضیحات را وارد کنید
4. ذخیره کنید

**نتیجه:**
- کامنت ثبت می‌شود
- Notification به درخواست‌کنندگان ارسال می‌شود

---

### 2. تایید مهندسی

**شرایط:**
- درخواست نباید متوقف باشد
- درخواست نباید قبلاً تایید شده باشد
- کاربر باید دسترسی تایید مهندسی داشته باشد

**مراحل:**
1. روی دکمه "تایید مهندسی" کلیک کنید
2. تایید کنید

**نتیجه:**
- `EngineeringAccept = true`
- تاریخ تامین محاسبه می‌شود (بر اساس LeadTime)
- Notification به واحد تدارکات ارسال می‌شود

---

### 3. تایید واحد فروش/پروژه

**شرایط:**
- درخواست باید تایید مهندسی داشته باشد
- تایید خودکار نباشد
- کاربر باید یکی از افراد مجاز باشد:
  - کارشناس فروش
  - مدیر فروش
  - مدیر پروژه

**مراحل:**
1. روی دکمه "تایید واحد فروش/پروژه" کلیک کنید
2. توضیحات تایید را وارد کنید
3. تایید کنید

**نتیجه:**
- `HasSalesUnitConfirmation = true`
- کامنت تایید ثبت می‌شود
- Notification به واحد تدارکات

---

### 4. ثبت توقف (Stop Workflow)

#### مرحله 1: ثبت توقف اولیه

**مراحل:**
1. روی دکمه "ثبت توقف" کلیک کنید
2. اطلاعات زیر را وارد کنید:
   - **نوع توقف**: صنایع یا مهندسی
   - **عامل توقف**: کاربری که باید بررسی کند
   - **ذینفعان**: افرادی که باید مطلع شوند
   - **علت توقف**: توضیحات
   - **پیوست** (اختیاری)
3. ذخیره کنید

**نتیجه:**
- `IsStop = true`
- `StopStatus = 2807` (ثبت اولیه)
- Notification به عامل توقف و ذینفعان
- مهلت پاسخ: 2 روز (Routine) یا 3 روز (Non-Routine)

#### مرحله 2: بررسی توسط عامل توقف

**مراحل:**
1. عامل توقف وارد می‌شود
2. روی "ثبت توقف" کلیک می‌کند
3. فرم بررسی نمایش داده می‌شود:
   - **نتیجه بررسی**: انتخاب از 5 گزینه
   - **توضیحات بررسی**
   - **دلیل تأخیر** (اختیاری)
   - فیلدهای خاص بر اساس انتخاب:
     - اگر "نیاز به اصلاح BOM": checkbox های Update/Delete
     - اگر "در انتظار مدیر پروژه": تاریخ تقریبی

**نتایج ممکن:**
- **2799** → `StopStatus = 2808` (نیاز به راه‌اندازی مجدد)
- **2800** → `StopStatus = 2810` (نیاز به اصلاح BOM)
- **2801** → `StopStatus = 2811` (نیاز به اصلاح مدارک)
- **2802** → `StopStatus = 2812` (حذف درخواست صنایع)
- **2803** → `StopStatus = 2813` (در انتظار مدیر پروژه)

#### مرحله 3: تصمیم درخواست‌کننده

**مراحل:**
1. درخواست‌کننده اولیه وارد می‌شود
2. فرم تصمیم‌گیری:
   - **راه‌اندازی مجدد** (2804) → `StopStatus = 2815`
   - **ثبت توقف مجدد** (2805) → `StopStatus = 2816` + فرم جدید
   - **حذف** (2806) → `StopStatus = 2817`

**توجه:**
- اگر "ثبت توقف مجدد" انتخاب شود، باید اطلاعات توقف جدید وارد شود

---

### 5. راه‌اندازی (Triggering)

**کاربرد:** برای درخواست‌های متوقف شده

**مراحل:**
1. روی "راه اندازی" کلیک کنید
2. تایید کنید

**نتیجه:**
- `IsStop = false`
- `Status = "راه اندازی شده"`
- کامنت راه‌اندازی ثبت می‌شود
- Notification به درخواست‌کنندگان

---

### 6. تغییر وضعیت

#### در راه (InWay)
- `Status = "در راه"`
- برای کالاهایی که در حال ارسال هستند

#### استعلام وضعیت (StatusInquiry)
- `Status = "در حال استعلام"`
- برای کالاهایی که از تامین‌کننده استعلام می‌شود

---

### 7. مدیریت پیوست‌ها

**مراحل:**
1. روی "مدیریت پیوست‌ها" کلیک کنید
2. لیست پیوست‌ها نمایش داده می‌شود
3. می‌توانید:
   - پیوست جدید اضافه کنید
   - پیوست موجود را دانلود کنید
   - پیوست را حذف کنید (فقط Admin)

**فیلدهای پیوست:**
- **نوع فایل**: DataSheet, DetailDrawing, WiringDiagram, ...
- **فایل**: حداکثر 10MB
- **توضیحات**: الزامی

**توجه:**
- برای برخی نوع فایل‌ها (DataSheet, WiringDiagram, TechnicalDocuments)
- Notification به واحد تولید ارسال می‌شود

### 8. خاتمه (Terminate)

**کاربرد:** حذف منطقی درخواست توسط کاربر

**مراحل:**

2. تایید کنید

**نتیجه:**
- `IsDeleted = true`
- `IsForceDeletedByUser = true`
- کامنت خاتمه ثبت می‌شود

## 🔐 نقش‌ها (Roles)

### نقش‌های اصلی:

| نقش | دسترسی‌ها |
|-----|-----------|
| **مهندسی** | تایید مهندسی، مشاهده درخواست‌ها |
| **واحد فروش/پروژه** | تایید فروش، مشاهده درخواست‌های تایید مهندسی شده |
| **واحد صنایع** | ثبت توقف، راه‌اندازی، مشاهده همه |
| **واحد تدارکات** | تمام عملیات، مدیریت کامل |
| **Admin** | تمام دسترسی‌ها |

### محدودیت‌های دسترسی:

1. **تایید مهندسی**: فقط کاربران با نقش Engineering
2. **تایید فروش/پروژه**: 
   - کارشناس فروش
   - مدیر فروش
   - مدیر پروژه
   - فقط برای درخواست‌های خودشان
3. **ثبت توقف**:
   - Admin همیشه
   - کاربر صنایع
   - درخواست‌کننده اولیه (در برخی مراحل)
   - عامل توقف (در مراحل خاص)
4. **راه‌اندازی**: واحد صنایع یا Admin
5. **در راه**: واحد تدارکات
6. **استعلام**: واحد تدارکات
7. **خاتمه**: فقط با دسترسی خاص

## ⚠️ نکات مهم

### 1. Stop Workflow پیچیده است!

**نکات کلیدی:**
- هر مرحله فیلدهای مخصوص خود را دارد
- Validation بر اساس StopStatus متفاوت است
- Navigation بین مراحل به صورت خودکار است

**Debug Tips:**
- همیشه `StopStatus` فعلی را چک کنید
- `_StopRequestPartial` به صورت دینامیک section ها را نمایش می‌دهد
- اگر فیلدی نمایش داده نشد، JavaScript console را چک کنید

### 2. Notification vs Email

در سیستم قدیم، مستقیماً Email ارسال می‌شد.  
در سیستم جدید:
1. Notification با `Type = Email` ایجاد می‌شود
2. یک Background Job باید Notification ها را پردازش کند
3. Email واقعی ارسال شود

**فایل Job:** `NotificationSenderJob.cs` (باید ایجاد شود)

### 3. File Upload

سیستم از `FileUploader` component استفاده می‌کند:
- فایل در file system ذخیره می‌شود
- رکورد در جدول `File` ایجاد می‌شود
- `AttachmentId` در Entity ذخیره می‌شود

**حداکثر حجم:**
- پیوست‌های عادی: 10MB
- پیوست‌های Stop: 5MB

### 4. Entity Relationships

```
OpenOrderRequest (اصلی)
  ├─> List<OpenOrderRequestComment> (کامنت‌ها)
  │    └─> Attachment (پیوست کامنت)
  │    └─> AlternativeAttachment (پیوست بررسی)
  ├─> List<OpenOrderRequestAttachment> (پیوست‌ها)
  │    └─> Attachment (فایل)
  ├─> Part (کالا)
  ├─> DL (تفصیل)
  ├─> EngineeringAcceptUser (کاربر تایید مهندسی)
  ├─> SalesUnitConfirmationUser (کاربر تایید فروش)
  ├─> ProductionOrder (سفارش ساخت)
  └─> ManCompany (تامین‌کننده)
```

## 🔍 Troubleshooting

### مشکل: Modal باز نمی‌شود

**راه‌حل:**
1. Console browser را چک کنید
2. مطمئن شوید `jquery-confirm` لود شده
3. مطمئن شوید `initPersionDatePicker()` وجود دارد

### مشکل: Validation کار نمی‌کند

**راه‌حل:**
1. `validateError()` function را چک کنید
2. مطمئن شوید `data-bind` attributes صحیح هستند
3. `data-invalidmessagespan` در همه input ها وجود دارد

### مشکل: فایل آپلود نمی‌شود

**راه‌حل:**
1. حجم فایل را چک کنید (حداکثر 5-10MB)
2. فرمت فایل را چک کنید (.pdf, .zip, .rar)
3. مطمئن شوید `FileUploader` component صحیح کار می‌کند

### مشکل: Notification ارسال نمی‌شود

**راه‌حل:**
1. جدول Notification را query کنید
2. مطمئن شوید Email کاربران صحیح است
3. Background Job برای ارسال Email فعال باشد

### مشکل: StopStatus به مرحله بعدی نمی‌رود

**راه‌حل:**
1. `DetermineNextStopStatusFromCheckingResult()` را چک کنید
2. مطمئن شوید Enum values صحیح هستند
3. Database را مستقیماً query کنید
